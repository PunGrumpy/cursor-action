## Notes on inputs

### `permissions`

Mapped to the SDK's tool allow and deny lists: `read-only` offers the read, search, and web tools only; `read-write` removes `shell` and `task` from the default toolset; `full` leaves the SDK default. It restricts the main agent loop and is not a sandbox. The full table is on [Behaviour](/behaviour).

### `cursor-version`

Ignored since v1.0.0. The SDK resolves the agent version itself, and pinning a Cursor build is no longer possible from this action. Passing anything other than `latest` emits a warning. The input is kept so existing workflows keep validating.

## Outputs

`summary` is model output. Pass it through `env:` instead of interpolating `${{ steps.<id>.outputs.summary }}` into a `run:` script or a `github-script` body, because interpolation splices text before execution. Every example on [Examples](/examples) follows this pattern.

`exit-code` is `0` when the agent run finishes successfully. It is `1` when the run times out, cancels, or encounters an error.

`status` reports the terminal state of the agent run: `finished`, `error`, or `cancelled`.

`duration-ms` reports the run duration in milliseconds when reported by the SDK.

`total-tokens`, `input-tokens`, and `output-tokens` report token counts from the run when available.
